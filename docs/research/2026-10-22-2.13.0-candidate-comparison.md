# 2.13.0 Candidate Comparison

Date: 2026-10-22, America/Toronto. Local evidence, not publication proof.

## Scope And Method

The combined candidate retires Task Transfer and includes ADRs 0072-0075.
It does not resume runtime experiments or claim the 3s Today / 5s first-30-day
targets. The reference is published `v2.12.5`, source
`dd6406930ea41d26af8f280032cc8e6bc3e290ef`.

One coherent read-only SQLite backup contains 884,576 usage events and 355,817
stored quota observations, 2,084,933,632 bytes. SHA-256:
`d82211645c0202c2cd860254011333779f06a5ecb247984ce3e310912ec0528a`.
Both sides use Python 3.13.12 / SQLite 3.50.4, the same installed dependencies,
fixed clock `2026-10-23T02:35:00+00:00` and America/Toronto calendar.

`scripts/benchmark_collector.py --mode report --workload dashboard-csv`
ran ten alternating unprofiled pairs after one excluded preparation pair.
First 30 days follows Today, so account-wide preparation is already available.
The append is a synthetic usage event plus a quota observation, not live capture.
All samples, including outliers, remain in private ignored evidence under
`output/performance/release-2.13.0/paired/`. No p95 or universal speedup is inferred.

Only the frozen input and one disposable working database were retained.
Guards denied original session files, external databases, networking and
subprocesses. Tests, browser checks and packaging did not overlap primary
measurements. No real capture, account request, raw-log copy or private upload
was involved. The backup and owned working databases were removed after the
final input-hash check; compact sources and measurements remain.

## Hosted Proof Failure And Deterministic Identity Correction

The first normal qualification,
[39895365576 attempt 1](https://github.com/Wenjun-Mao/codex_usage/actions/runs/39895365576),
used `f5800d1afbb9fd33b2c7237a0790f00ba50474bd`. Metadata, both platform
packages and all five visual gates passed. All 2,901 Python cases passed in
231.05s, followed by successful Ruff and monetary/work parity. Core receipt
generation then rejected a missing required identity; freeze and native
acceptance were correctly skipped. No dry-run, tag or publication was performed.

The required-case amendment had exposed a pre-existing randomized parameter in
`test_correlation_rejects_noncanonical_values`: `uuid4().upper()` became part of
the pytest case name. Two independent full collections reproduced exactly one
different identity among 2,901 cases. This is a test-fixture/identity contract
failure, not missing test execution or an accounting failure.

Use a fixed representative uppercase UUID and semantic `uppercase-uuid` ID.
The newly pinned identity is replaced in both the baseline and amendment's
added set; every original unrelated requirement remains unchanged. No wildcard
UUID matching, case exemption, skip or weakened verifier is introduced.

The verifier now has a thin local command using the same complete-collection,
preserved-case and no-skip function as hosted receipt generation. Positive and
consistently missing-case negative CLI tests are pinned. The release guide runs
the collection plugin and JUnit output together, then validates both before CI;
this output is explicitly local-only and cannot act as release proof.

After correction, two independent collections are identical across all 2,903
cases, SHA-256 `0fb6dec245173f780481546a488259f108614b6c429558771b2d2a2142230d64`.
The instrumented complete suite passes 2,903 cases in 105.74s and its actual
JUnit/collection evidence passes the local release validator with zero skips.
Ruff and exact accounting/work parity pass again. Product runtime source and
the timed comparison are unchanged by this correction.

The failed run remains preserved. A fresh full qualification was requested,
not automatically retried. Changed source/qualification inputs require fresh
proof and packages; successful packages from the failed candidate are not
promotable evidence for the corrected source.
