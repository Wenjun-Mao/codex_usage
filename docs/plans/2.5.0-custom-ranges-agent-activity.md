# Codex Usage 2.5.0 Custom Ranges And Agent Activity

## Status

Approved on 2026-09-07.

## Outcome

Add calendar-date filtering and a permanent Agent Activity breakdown using data
already stored in the durable ledger. Changing ranges, viewing agent totals, and
exporting CSV remain ledger-only and must not open Codex JSONLs or trigger a
capture.

## Scope And Decisions

### Date Range Contract

- Introduce a canonical report-range value containing the range kind, inclusive
  local start and end dates, half-open UTC bounds, display label, timezone, and
  stable cache identity.
- Preserve `today`, `yesterday`, `7d`, `30d`, `month`, and `all`.
- Extend `/v1/report` additively with `range=custom`,
  `start_date=YYYY-MM-DD`, and `end_date=YYYY-MM-DD`.
- Require both custom dates, permit a single date by making them equal, reject
  reversed, malformed, or future ranges, and interpret dates in the agent's
  configured timezone. Resolve the inclusive end date to the next local
  midnight so DST boundaries remain correct.
- Include the resolved bounds in the render-cache key for custom and moving
  preset ranges. This also prevents a named-range cache hit from crossing a
  local day or month boundary.
- Show friendly calendar labels instead of exposing `custom`.
- Use daily trends for custom ranges up to 90 days. Longer custom ranges use the
  existing script-free Week/Month view while retaining exact daily details.
- Keep agent API version 1 because the change is additive. Advertise
  `custom-report-range` and `agent-activity` capabilities through health and
  status so independently updated clients can report an outdated collector
  clearly.

### Client Experience

- Add **Custom date range...** to the native and VS Code range selectors.
- Use an accessible Start/End modal in the native app and sequential validated
  date inputs in VS Code.
- Default a first custom selection to the latest seven calendar days and reuse
  the previous custom selection thereafter.
- Persist this UI state per client, not in agent settings: native local storage
  and VS Code global state.
- Apply the selected range to the complete Usage report. Task Storage remains
  date-independent, and cancelling leaves the current report untouched.

### Agent Activity

- Add Agent Activity after the temporal charts and before Project Breakdown.
- Build it from the same filtered `UsageRecord` collection already loaded for
  the report. Do not add a ledger table, migration, source scan, or second
  valuation pass.
- Show a daily summary with Total, Input, Cached Input, Output, Reasoning,
  Responses, active root tasks, and active subagents.
- Show range totals per agent with role, root task, project attribution, active
  days, requested token categories, response count, and total tokens.
- Define one response as one positive cumulative-usage delta recorded by the
  parser. Disclose that this includes tool-driven or internal model cycles and
  is not a user-message count. Cached input remains part of Input and reasoning
  remains part of Output.
- Resolve nested agents to their top-level root through the ledger task-parent
  graph with cycle and missing-parent safeguards.
- Group each agent once by task ID. If transitioned usage spans projects, list
  all applicable projects instead of duplicating the agent.
- Prefer a stored non-ID title; otherwise show Root or Subagent plus a shortened
  task ID while retaining the complete ID.
- Display the 50 highest-token agents, disclose the complete count, and keep the
  section compact and horizontally scrollable.

### Complete CSV Export

- Add **Export Agent Activity CSV** to Usage controls in both clients.
- Add an authenticated endpoint returning complete agent-by-day rows for the
  current range and project filters.
- Export date, agent ID and label, role, root task ID, project keys and labels,
  Input, Cached Input, Output, Reasoning, Total, and Responses as UTF-8 CSV with
  no display limit.
- Save through VS Code's file dialog. Add a narrow Tauri host command using the
  existing dialog plugin to select and write the destination.
- Use a deterministic range-based filename. Export may repeat the ledger query
  when explicitly requested but must never read task files.

## Non-Goals

- No ledger schema change, new capture data, persistent aggregate table,
  transcript inspection, telemetry, pricing-by-agent view, or arbitrary
  timestamp range.
- Exact agent-by-day detail belongs in CSV; the dashboard remains a compact
  summary.

## Acceptance Evidence

- Preset and custom bounds cover same-day ranges, DST changes, month and year
  boundaries, malformed/reversed/future dates, friendly labels, and cache
  rollover at local midnight.
- Daily, per-agent, role, root-task, and agent-day totals conserve every token
  category and response count against the filtered ledger records.
- Nested agents, missing parents, cycles, transitions, agents spanning projects,
  empty ranges, and absent friendly titles are covered.
- A five-day `narrative-forge` result matches an independent SQLite/Python oracle
  without committing local corpus values.
- The dashboard shows no more than 50 agents while CSV contains all agent-day
  rows and exactly conserves the selected totals.
- Native and VS Code tests cover persistence, cancellation, validation,
  capability mismatch, export dialogs, and Unicode CSV values.
- Range changes, Agent Activity, and CSV export open zero JSONLs and request no
  capture.
- `uv run pytest -q`, `uvx ruff check .`, extension build/tests/package checks,
  native type checks/tests/build, Rust tests, Playwright visual checks, macOS
  packaging, and the non-publishing macOS/Windows native workflow pass.
- Product and Marketplace documentation, canonical screenshots, all version
  surfaces, lockfiles, and changelogs identify `2.5.0`. ADR 0041 records the
  durable range and agent-activity contract, and the report renderer revision
  invalidates cached 2.4.x HTML.
- The integrated release is merged to local `main`, pushed, tagged `v2.5.0`,
  published through the established dual-VSIX workflow, and verified together
  with the native preview artifacts.

## Execution Authority

The director owns scope, consequential decisions, escalations, and final
evidence-based acceptance. One bounded coordinator owns implementation
planning, executor supervision, debugging, integration, verification, and the
already-authorized release. Material changes to scope, acceptance, risk, or
external authority must return to the director; routine technical decomposition
does not.
